# Тюнинг сети

Против «TikTok и Instagram грузятся рывками». Применяется в конце `full`, отдельно — пункт меню **7** или:

```bash
meridian tune
```

Можно запускать повторно: правки не дублируются.

## Почему лагает

Канал РФ↔Европа длинный (40–60 мс) и с потерями. Дефолтный cubic на первой же потере режет скорость вдвое, а мелкие буферы не дают разогнаться. Плюс nginx по умолчанию копит xhttp-поток у себя и держит всего 1024 соединения на воркер.

## Ядро

Файл `/etc/sysctl.d/99-zz-meridian-net.conf`:

| Что | Зачем |
|---|---|
| BBR + fq вместо cubic | не режет скорость на каждой потере |
| TCP-буферы до 16 МБ | заполнить трубу на RTT 40–60 мс |
| `tcp_slow_start_after_idle = 0` | пауза между роликами не сбрасывает скорость к нулю |
| `tcp_notsent_lowat = 32768` | меньше bufferbloat у ws/grpc/xhttp |
| MTU probing | клиенты за PPPoE и туннелями не виснут на больших пакетах |
| RACK, терпимость к reordering | мобильные сети и DPI переставляют пакеты |
| ECN выключен | DPI портит ECN-биты, это сбрасывает окно BBR |
| быстрые таймауты мёртвых сокетов | мобильный NAT, обрывы |
| conntrack 262k, established 2 ч | иначе таблица забивается и новые соединения молча дропаются |
| порты 10000–60999 | `127.0.0.1:61000` остаётся свободным для внутреннего API xray |

!!! warning "Что намеренно не трогается"
    `ip_forward`, `rp_filter` и `udp_mem` остаются системными. `ip_forward = 0` отрезает docker-контейнерам
    интернет, strict `rp_filter` ломает WARP и мосты, а фиксированный `udp_mem` меньше авто-значения ядра.

Файл назван `99-zz-…`, чтобы применяться последним и не перебиваться node-accelerator и другими `99-*`.

## nginx

- 16384 соединений на воркер вместо 1024, `worker_rlimit_nofile 65535`.
- xhttp без буферизации: `proxy_buffering off`, `proxy_request_buffering off`.
- Часовые таймауты: поток не рвётся через 60 секунд.

Перед правкой делается бэкап (`*.bak.<время>`). Если `nginx -t` не проходит, бэкап возвращается сам.

## Откат

```bash
rm /etc/sysctl.d/99-zz-meridian-net.conf && reboot
```
